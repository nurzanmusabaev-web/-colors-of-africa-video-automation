# Перемонтаж: почему уходят на 28-й секунде

Данные ролика `rBcW0cOUvCw` через 5 дней после публикации:

| | |
|---|---|
| Показы | 243 |
| CTR | ~2.9% |
| Среднее удержание | **0:28 из 11:50 = 3.9%** |
| Заголовок / превью | 85 и 85 из 100 |

Упаковка сработала — люди зашли. Ушли из-за содержания.

Важно: первые 105 секунд фильма **анимированы**, там нет статики. Значит уход на
28-й секунде вызван не слайдшоу, а тем, что за эти 28 секунд зрителю ничего не
пообещали. Он видит беременную львицу в траве, заросли, роющие лапы — красиво и
без единой причины остаться.

Это ошибка сценария. В `channel/profile.yaml` заложено `cold_open_sec: 30`, но в
молчаливом сценарии на 123 кадра холодное открытие не применено.

## Как чинится без единой новой генерации

Оба нужных клипа уже скачаны.

```
0:00-0:07   14_07   бросок: львица валит бородавочника, взрыв пыли
0:07-0:14   14_14   стоит над добычей, кровь на морде, пустая равнина
0:14-0:16   чёрное поле, звук уходит в тишину
0:16 -->    0_00    беременная львица идёт по траве, дальше фильм как есть
```

Зритель за четырнадцать секунд получает вопрос: **как она к этому пришла?**
Сейчас он получает пейзаж.

Финальные кадры остаются на своих местах в конце. Повтор здесь работает: в начале
это обещание, в конце — расплата.

Сборка холодного открытия:

```bash
ffmpeg -y -f lavfi -i color=black:s=1920x1080:r=30:d=2 -c:v libx264 -crf 17 -pix_fmt yuv420p black.mp4
printf "file '14_07.mp4'\nfile '14_14.mp4'\nfile 'black.mp4'\n" > cold.txt
ffmpeg -y -f concat -safe 0 -i cold.txt -c copy cold-open.mp4
```

Дальше `cold-open.mp4` встаёт первым в общий список склейки.

## Перезаливать, а не заменять файл

YouTube уже поставил этому ролику оценку по удержанию 3.9%, и замена файла её не
снимает. Перемонтированную версию нужно грузить **как новый ролик**: он получает
чистый тест на новой аудитории. Старый можно оставить или скрыть.
